### Added
- **The database architect now joins planning, and it recommends before it designs.**
  `orion run <id> --stage database` gathers what is committed — the intent capture, the
  spec, the plan — and recommends a database **with its reasoning**: what it weighed,
  what it rejected, and what would have to change for the answer to be wrong. A report
  that names an engine and argues nothing is refused and nothing is recorded, because
  "Postgres" on its own is not something anybody can evaluate when they confirm it or
  revisit in a year. The recommendation is written unconfirmed to
  `docs/recommendations/pending/<KEY>-database.md` and asked about in Slack; only once
  somebody on `slack.merge_approvers` confirms it is the initial schema designed — and
  it is designed against the confirmed record itself, not a paraphrase of it. The schema
  then goes through the same flow as `<KEY>-schema`. Neither the database nor the schema
  is readable by any later stage until it is confirmed, so nothing is ever built against
  a data model nobody agreed to. The command is resumable: run it again after the
  reaction and it picks up where the confirmation left it. `orion plan` prints it beside
  the stage chain when the idea puts the database architect on the run.
