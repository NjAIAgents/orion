### Added

- `orion new` is now the interactive front half of the flow. It elaborates a
  flat-text idea into a full project description by asking who it is for, the
  problem, what is out of scope and what success looks like; has you finalise
  the project name; and creates the tracker project with that description. It
  is the one place in Orion that holds a synchronous exchange, because it is
  the one place a human is present by definition. An answer left blank is
  recorded as an open question rather than dropped, so the existing discovery
  gate still blocks on it.

### Changed

- The Jira project is created by `orion new` rather than later by
  `orion provision`, and is created with the elaborated description instead of
  a placeholder. Creation goes through the same describe-then-confirm gate
  `orion init` uses, which states before asking that a Jira project cannot be
  deleted without admin rights.
- `orion provision` no longer creates a tracker project for a workspace that
  already has one; it reports the existing binding. Previously a second run
  would have created a duplicate project under a fresh key.
- The workspace directory, git repo and Jira project are all named from the
  project name you finalise, rather than the workspace being named from the
  raw idea and the tracker from something derived separately.
- `--skip-discovery` skips the exchange, as does running without a terminal.
  Both fall back to the idea as typed and a name derived from it.
