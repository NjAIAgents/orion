### Fixed

- `procsafe.WriteFile` could publish a mixture of two writers when both ran
  inside the same process. Its temporary file was named from the pid and the
  clock, and every goroutine in one process shares a pid, so two starting
  within the same nanosecond tick opened the SAME temporary file, interleaved
  into it, and renamed the blend into place. Across processes it was always
  safe; within one it was not, which is the case parallel agents inside a
  single run are made of. It now uses `os.CreateTemp`, whose uniqueness the
  kernel guarantees, and restores the caller's file mode before publishing so
  the visible file is never briefly 0600 (OR-180).
