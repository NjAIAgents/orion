### Added

- The CI fix loop now triages a failing job's log through a cheap subagent
  before handing it to the fix run, so the raw log no longer rides along on
  every turn of that run: only a short report of what broke and why does. A
  CI log runs to thousands of lines, and everything in a prompt is re-sent on
  every turn, so the log was being paid for repeatedly to say one thing once.
  The triage run is attributed to its own log-triage actor (haiku by default,
  configurable like any other agent through `orion config agents`) and its
  spend appears as its own row in the ticket's cost report rather than hiding
  inside the fix run's total. If triage fails for any reason the fix run gets
  the raw log exactly as before, so this can only reduce what is sent, never
  withhold it (OR-143).
