### Fixed

- **A batch now closes the tickets it landed.** When a batch merged, its members were
  left carrying `orion-ready` and sitting in whatever status they were in. The work was
  on the work branch and the tracker did not know. Worse, the queue label was still
  there, so the next pass picked the same ticket up again and rebuilt a batch out of
  work that had already shipped. The per-branch path had always cleared labels,
  transitioned to Done and commented; the batch path never grew the equivalent. It does
  now, including the child sub-tasks, and a tracker that refuses one of those steps is
  reported rather than allowed to stop the ones after it -- a ticket marked Done with a
  stale label is a smaller problem than a merged ticket left In Progress.

- **The batch stopped asking for the same approval twice.** The approval record was
  forgotten on the way out, and since every batch uses the same ref name, the next pass
  found no record, decided nobody had been asked, and posted the request again. Observed
  as four asks for two batches, each already carrying a green tick -- and every duplicate
  is a message whose reaction may then be read from the wrong one. The record is kept
  now and compared by MEMBERS, so a genuinely different set of tickets on the same ref
  still asks afresh while the same batch stays quiet.

- **Watch output stopped repeating the recent-lines frame.** The window was drawing its
  frame into the scrolling region on every write, so the pane's header appeared over and
  over down the terminal instead of once above the rows.
